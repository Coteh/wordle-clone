# wordle-clone

See `README.md` for what the game does and how to play it. The thing to know before editing:
the same game logic drives two frontends — a browser app and a terminal CLI — in plain
JavaScript, with no TypeScript, no bundler, and no framework.

## Commands

`README.md` → **Development** and **Testing** cover installing, the dev servers, mkcert
setup, the optional ImageMagick icon labelling, and `pnpm build`. Read it rather than
guessing; what follows is only what it does not say.

- `pnpm install` — pnpm 10.20.0. `.nvmrc` pins Node 18; CI runs the unit tests on Node 20.
- `pnpm test` — mocha unit tests in `test/`. Takes under a second; run it on every change.
- The Cypress suite expects the dev server on 5501 (`baseUrl` in `cypress.config.js`), so it
  needs `pnpm devs` and its certs, not `pnpm dev`.
- Never commit `words.txt`. The README has you regenerate it locally to avoid spoilers, so a
  changed word list in a diff is almost always that scrambled copy.

There is no linter and no typechecker. `pnpm test` plus the Cypress suite is the whole local
gate.

## Project layout

- `index.html` — the whole browser app shell. Scripts are plain `<script>` tags in
  dependency order. There are no ES modules and no imports in the browser path: every
  `src/*.js` file shares one global scope, so a `const` at the top level of `src/render.js`
  is visible to `src/index.js`. Adding a file means adding a `<script>` tag.
- `src/game.js` — game logic, shared by both frontends. It branches on
  `typeof process !== "undefined"` to pull in CLI-only dependencies, and exports through
  `module.exports` only in the Node path. Keep this file free of DOM access.
- `src/index.js` — browser entry point. Wires the renderer object to the event handler that
  `initGame` drives.
- `src/render.js` — DOM rendering (keyboard, dialogs, notifications).
- `src/storage/`, `src/share/` — an `index.js` interface with `browser.js` and `cli.js`
  implementations behind it.
- `cli.js` — terminal frontend, same game logic.
- `words.txt` — the word list, generated by `scripts/gen_word_list.sh`.

## Code style

Prettier with the repo's `.prettierrc`: 4-space indent, 100 column width. Prettier is not a
dependency and formatting is not enforced in CI, so **match the surrounding style rather
than reformatting whole files** — the current code was written against Prettier 2 defaults,
and a modern Prettier rewrites unrelated lines (trailing commas, quote style, wrapped
function signatures). Check your own diff, not the file:

```sh
npx prettier@3 src/render.js | diff -u src/render.js - # new lines should be the only hits
```

Prefer the idioms already in the file over a "better" pattern imported from elsewhere.

Comment only what the code cannot say, and keep it to one line per section. Skip anything a
well-named call, the symmetry with nearby code, or the very next line already makes clear.
The comments that earn their place explain why code sits where it does, or a constraint that
is invisible on the page. Reasoning about why one approach beat another belongs in the commit
message, where it will not go stale.

## Testing

- Game logic, storage, dates, sharing, migrations → unit tests in `test/` (mocha, sinon,
  mock-fs).
- Anything touching the DOM, input handling, dialogs, or event listeners → e2e coverage in
  `cypress/e2e/`. `cypress/support/commands.js` has the helpers (`cy.keyboardItem`,
  `cy.inputRow`, `cy.inputRowHasWord`, `cy.waitForGameReady`).
- Specs mock only `Date` (`cy.clock(..., ["Date"])`) so real `setTimeout`/`setInterval`
  behaviour still runs. Keep that when adding specs that depend on timers.
- Resource-lifecycle bugs (a listener or timer that is registered per render and never
  removed) are best covered by stubbing `addEventListener` / `setInterval` on the window and
  asserting the count, since the symptom is invisible in the DOM.

## CI

`.github/workflows/ci.yml` runs two jobs on every push: `test-game-logic` (`pnpm run
test-ci`, mocha with the JUnit reporter) and `cypress-run` (mkcert certs, `pnpm run devs`,
the real Cypress suite in Edge). Both publish JUnit XML. Keep both green before asking for
review.

## Commits and pull requests

Match the existing history: a short imperative subject line, then body paragraphs
explaining what was wrong and why the fix works. No trailers.

`CHANGELOG.md` follows Keep a Changelog and is updated in its own commits, not alongside
every fix.

Never carry issue-tracker or agent metadata into the repository:

- No issue-tracker references anywhere in pushed content — no ticket identifiers like
  `COT-123`, no tracker URLs, no `Fixes <ticket>` trailers — in commit messages, PR titles,
  PR descriptions, code comments, or changelog entries. Describe the change on its own terms.
- No agent session links, no "Generated with <tool>" footers, no session or co-author
  trailers naming an assistant, and no model names (`claude-*`, `gpt-*`, `gemini-*`, and the
  like) in commit messages, PR titles, PR descriptions, or any file pushed to the repository.

## Agent instruction files

This file is the source of truth, and every rule belongs here. `CLAUDE.md` exists only
because Claude Code reads `CLAUDE.md` and not `AGENTS.md`; it is a single `@AGENTS.md`
import line. Keep it that way — do not let an `/init`-style command copy this file's
contents into it, since duplicated instructions drift apart and nothing says which copy is
current.

## Environment gotchas

- Cypress binaries download from `download.cypress.io`, which is blocked in some sandboxed
  agent environments, so `pnpm cypress:run` cannot run there. Install with
  `CYPRESS_INSTALL_BINARY=0` to get the rest of the dependencies, run the mocha tests, and
  drive the app in a real browser by hand to check behaviour. CI runs the real suite. Where
  the sandbox ships Chromium and Playwright — Claude Code web sessions have them, with the
  browsers at `PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers` — serving the repo root and
  scripting the interaction is how DOM and input-handling changes get verified.
- The app fetches `words.txt` at the site root, so a plain static server over the repo root
  is enough to exercise the browser game without `pnpm build`.
